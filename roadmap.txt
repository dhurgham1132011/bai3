1. 🎯 نظرة عامة وفكرة المشروع (Web-Based Core)
الاسم المقترح: المجهز أو البضاعة (أو اسم عراقي مناسب).
الهدف: إنشاء منصة ويب رئيسية (Web Platform) ورقمية متكاملة لربط تجار التجزئة وأصحاب المحلات (المشترين) مباشرة بـ تجار الجملة والموزعين والمجهزين (الموردين) في العراق، مع تطوير تطبيق موبايل يعتمد على هذه المنصة لتسهيل تجربة الاستخدام المتنقل.
💡 وصف الفكرة التفصيلي
المشروع هو نظام سوق إلكتروني (E-Marketplace) يعمل بنظام B2B، مبني بشكل أساسي على تطبيق ويب تفاعلي ومحسّن للاستخدام على متصفحات الحاسوب والجوال.
•	العمود الفقري: تطبيق الويب هو المكان الذي يتم فيه إدارة جميع العمليات المعقدة، من إضافة المنتجات وإدارة الطلبات (للموردين) إلى تصفح الكتالوجات وتقديم الطلبات (للمشترين).
•	الوصول عبر الموبايل: سيتم توفير تطبيق موبايل (Native/Hybrid) للمشترين والموردين، يتميز بـ:
o	تجربة مستخدم مُركزة: يركز على المهام السريعة مثل تتبع الطلب، وتلقي الإشعارات الفورية، وتصفح سهل على الهاتف.
o	اعتماد كلي على API الويب: يستمد جميع بياناته ووظائفه من الواجهات البرمجية (API) التي تخدم تطبيق الويب.

2. ⚙️ المتطلبات التقنية الأساسية (Web-Centric Architecture)
الجانب التقني	التقنية المُعتمدة	الملاحظات والتبرير
الباك إند (Back-End) & API Core	PHP (Laravel/Symfony)	لغة قوية ومستقرة، تستخدم لبناء API RESTful مركزي يخدم كلاً من تطبيق الويب وتطبيق الموبايل، لضمان تزامن البيانات وكفاءة العمليات.
قواعد البيانات (Database)	MySQL	نظام إدارة قواعد بيانات علائقي (RDBMS) فعال ومناسب لتخزين بيانات المستخدمين، المنتجات، الطلبات، والمعاملات المالية.
تطبيق الويب (Front-End Core)	React.js / Vue.js	لإنشاء واجهة ويب تفاعلية (SPA - Single Page Application) قوية وسريعة للموردين (لوحة التحكم) وللمشترين (واجهة التصفح).
تطبيق الموبايل (Mobile App)	React Native / Flutter	كتطبيق واجهة أمامية ثانوية، يستخدم نفس الـ API لتقديم تجربة مُحسّنة على Android و iOS، مع التركيز على المشتري والمورد لتلقي الإشعارات الفورية.
التخزين السحابي	AWS S3 أو ما يعادله	لتخزين صور المنتجات والمستندات، لضمان سرعة تحميل عالية في واجهة الويب والموبايل.

3. 👤 نماذج المستخدمين وتجربة الاستخدام (UX/UI)
نماذج المستخدمين تبقى كما هي، لكن مع تحديد نقطة الوصول الأساسية:
نموذج المستخدم	الوصف	المسار الأساسي (Core Journey)	نقطة الوصول المفضلة/الأساسية
1. تاجر التجزئة (المشتري)	صاحب محل بقالة، صيدلية، متجر ملابس، إلخ.	تسجيل ➡️ بحث بالمنتج ➡️ مقارنة الأسعار ➡️ إضافة للسلة ➡️ تأكيد الطلب والدفع ➡️ تتبع الشحنة.	تطبيق الموبايل (لسهولة التصفح المتنقل والإشعارات) والويب (للطلبات الكبيرة).
2. تاجر الجملة (المورد/المجهز)	شركة توزيع، منتج، مستورد، أو موزع رئيسي.	تسجيل ➡️ إضافة وإدارة المنتجات والمخزون ➡️ تلقي الإشعارات بالطلب ➡️ قبول الطلب وتجهيزه ➡️ تحديد الشحن ➡️ مراجعة المدفوعات.	تطبيق الويب (لإدارة الكتالوجات المعقدة والمخزون) والموبايل (لتلقي إشعارات الطلبات الفورية).
3. المدير (Admin/الإدارة)	إدارة المشروع وفريق العمليات والمالية.	مراقبة جميع العمليات ➡️ إدارة المستخدمين ➡️ مراجعة المدفوعات والعمولات ➡️ حل النزاعات ➡️ إدارة الفئات.	تطبيق الويب / لوحة التحكم الإدارية (لكونها تتطلب شاشة واسعة وإمكانيات تقارير متقدمة).

4. 🖼️ وصف الواجهات التفصيلي (UI/UX) - API Driven
جميع الواجهات (للوجب والموبايل) سيتم تطويرها باستخدام React/Vue.js (للويب) أو React Native/Flutter (للموبايل) ولكنها تعتمد بالكامل على نفس الـ PHP/MySQL API.
أ. واجهات تاجر التجزئة (المشتري)
الواجهة	الوصف التفصيلي وعناصر التحكم	API / DB Integration (العمود الفقري)
الصفحة الرئيسية (ويب وموبايل)	شريط بحث ذكي، قائمة الأقسام، العروض المميزة، "طلب مكرر".	API: لجلب الأقسام، العروض، وقائمة الطلبات السابقة للمستخدم. DB: categories, promotions, orders.
صفحة المنتج بالجملة	صور المنتج والوصف، سعر الجملة و الحد الأدنى للطلب (MOQ)، اسم المورد وتقييماته.	API: جلب تفاصيل المنتج، المخزون، والمورد. DB: products, suppliers, product_inventory.
السلة والدفع	ملخص الطلب، اختيار العنوان، اختيار طريقة الدفع.	API: حساب إجمالي الطلب، إنشاء سجل الطلب (Create Order)، تحديث المخزون. DB: shopping_cart, orders, order_items.
ب. واجهات تاجر الجملة (المورد) - لوحة التحكم (الويب هي الأساس)
الواجهة	الوصف التفصيلي وعناصر التحكم	API / DB Integration (العمود الفقري)
لوحة تحكم المورد (الويب)	إحصائيات سريعة، قائمة "طلبات جديدة" (New Orders)، أزرار سريعة: إضافة منتج، إدارة المخزون.	API: جلب البيانات الإحصائية والطلبات المعلقة. DB: Aggregation queries on orders and order_items tables.
إدارة المنتجات والمخزون (الويب/الموبايل)	نموذج "إضافة منتج": يتضمن إدخال: الاسم، الوصف، الفئة، الصور، سعر الجملة، الكمية المتاحة (Stock).	API: إرسال/تعديل سجلات المنتجات والمخزون. DB: products, product_inventory.
تتبع الطلبات والشحن (الويب والموبايل)	قائمة الطلبات، مع فلترة حسب الحالة. زر لتغيير حالة الطلب عند كل مرحلة.	API: تحديث حقل order_status في جدول الطلبات. DB: orders, notifications.

5. 💰 هيكل قاعدة البيانات المقترح (MySQL)
الهيكل يبقى ثابتًا لخدمة كل من تطبيق الويب والموبايل، حيث أنه العمود الفقري للبيانات:
•	users: لتخزين بيانات كل من المشترين والموردين والمدراء.
o	الحقول: id, username, phone_number, password_hash, user_type (M=مشتري، S=مورد، A=مدير), store_name, address.
•	categories: لتخزين فئات المنتجات.
•	products: لتخزين بيانات المنتجات.
o	الحقول: id, supplier_id (FK), category_id, name, description, wholesale_price, min_order_quantity (MOQ).
•	product_inventory: لتتبع المخزون لكل منتج.
•	orders: لتخزين بيانات الطلبات الرئيسية.
o	الحقول: id, buyer_id (FK), order_date, total_amount, shipping_address, payment_method, order_status.
•	order_items: لتخزين تفاصيل محتويات كل طلب.
